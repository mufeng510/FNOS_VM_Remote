# iPhone 快捷指令 + NFC 配置教程

iPhone 碰一下 NFC 标签即可开机 / 正常关机 Windows 虚拟机。不需要 Home Assistant、不需要额外 App。

**原理**：NFC 标签本身不存任何数据，仅作为快捷指令的"触发器"。快捷指令通过 HTTP 调用应用的 API，Token 保存在快捷指令内部（不在标签上）。

**前提**：iPhone 与 FNOS 在同一局域网（家庭 Wi-Fi）。出门流量网络下不可用。

## 准备

1. 已安装本应用并配置好端口（默认 8321）。
2. 已获得 Token（初始 Token 在安装时的 `initial-token.txt`；或在应用「Token 管理」中重新生成）。
3. 确认手机能访问：`http://<FNOS-IP>:<端口>/api/v1/health`（浏览器打开应看到 JSON）。
4. 两个 NFC 标签（常见的 NTAG213 贴纸即可，一张贴在"开机位置"，一张贴在"关机位置"）。

## 第一步：创建开机自动化

1. 打开 iPhone「快捷指令」App → 底部「自动化」→ 右上角 **+** →「个人自动化」。
2. 向下滑，选择「**NFC**」。
3. 点「扫描」，将开机标签贴到 iPhone NFC 感应区（顶部，靠近后置摄像头）。
4. 给该 NFC 命名（如"开机标签"）→ 下一步。
5. 添加动作：搜索「**获取 URL 内容**」，添加。
6. 配置该动作：
   - URL：`http://<FNOS局域网IP>:<端口>/api/v1/vm/start`（例如 `http://192.168.1.10:8321/api/v1/vm/start`）
   - 方法：**POST**
   - 下方展开「头部」：添加一个请求头，键 = `Authorization`，值 = `Bearer <你的Token>`
7. 再添加动作：「**显示结果**」，内容选「获取 URL 内容的结果」。
   - 可选：再加一个「If」动作判断 `success` 是否等于 `true`，分别显示"已开机"或"已在运行"。
8. 关闭「运行前询问」（如 iOS 版本提供该选项），完成。

## 第二步：创建关机自动化

与开机完全相同，仅两处不同：

1. 使用另一个 NFC 标签（"关机标签"）。
2. URL 改为：`http://<FNOS局域网IP>:<端口>/api/v1/vm/shutdown`

其余完全一致（POST + Authorization 请求头 + 显示结果）。

## 第三步：实际使用

- 碰开机标签 → 收到触发 → 快捷指令发起 POST → Windows 开机；返回 JSON 会用「显示结果」弹出（含 `state` 与 `message`）。
- 碰关机标签 → Windows 正常关机；关机过程需要时间（默认等待最多 120 秒），快捷指令会在收到响应后显示结果。

## 常见情况

| 情况 | 快捷指令表现 |
|---|---|
| 已开机又碰开机标签 | 返回 `success: true, already: true, message: "虚拟机已在运行中"`，不会重复开机 |
| 已关机又碰关机标签 | 返回 `success: true, already: true` |
| Windows 关不掉（超时） | 返回 `success: false, timed_out: true`，未强制断电，请检查 Windows |
| 返回 401 | Token 错误或已更新；重新复制最新 Token 替换请求头 |
| 网络不通 | 确认 iPhone 在家庭 Wi-Fi，未用蜂窝/流量 |

## 端口修改后怎么办

快捷指令中的 URL 端口需要手动改成新端口：

1. 打开快捷指令 → 找到对应自动化 → 编辑 → 「获取 URL 内容」动作 → 修改 URL 中的端口。
2. 两个标签都改。Token 不用改。

## 限制说明（重要）

- **NFC 标签不存 Token**，仅触发器；Token 泄露风险取决于你如何保护快捷指令本身。
- 快捷指令访问 NAS **必须处于家庭局域网**；出差/在外用蜂窝网络无法触达。
- **iOS 版本差异**：不同 iOS 版本对 NFC 自动化的运行确认、解锁状态、后台运行策略存在差异（部分版本需解锁并点一下确认），**请以你的 iPhone 实际行为为准**，本文不承诺完全无交互。
- 关机 API 会等待直到 Windows 确实关机或超时；如果 Windows 正在更新/卡住，快捷指令会等到超时才返回——这是正常行为，不会强制断电。

## 排错

1. 快捷指令"获取 URL 内容"报错 → 先在 iPhone Safari 打开 `http://<FNOS-IP>:<端口>/api/v1/health` 验证网络可达。
2. 返回 401 → Token 不对，复制粘贴时注意不要带前后空格。
3. 返回成功但 VM 没反应 → SSH 或应用日志确认；应用内「操作日志」可看到每次请求的结果。
